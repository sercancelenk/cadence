# AI Phase 0b, 2 and 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build everything still open in the AI roadmap: the engine additions streaming (F4b), image input (F4c) and embeddings (S2), then Phase 2 (T2 Eisenhower, N3 structure a scratchpad, D2 mock data, D1 ERD from text, D4 sketch to Mermaid, H1 digest) and Phase 3 (P2 1:1 prep, D5 screenshot to Mermaid/HTML, S1 Ask Workspace).

**Architecture:** Same as Phase 1: each feature is a registry task (`src/lib/ai/prompts/*.ts`: versioned prompt, strict parser, fixtures) run by `runAiTask`, shown in `AiResultPanel`, applied only on an explicit button through existing actions. A new hook `useAiRun` carries the scaffolding every dialog repeated (gates, blocked/error/truncated, abort on unmount, streaming text), so the new dialogs stay small. The engine gains three optional capabilities that default to off; nothing existing changes behaviour.

**Tech Stack:** React 18, strict TypeScript, Vitest + Testing Library, Electron main process (`net.fetch`, IPC events for streaming), Mermaid 11, `@xyflow/react` (ERD), TipTap.

**Spec:** `docs/superpowers/specs/2026-10-24-ai-features-design.md` (5.4, 6 Phase 2 and 3, 7). Foundation plan: `docs/superpowers/plans/2026-10-24-ai-foundation-phase-0a.md`; Phase 1 plan: `docs/superpowers/plans/2026-10-25-ai-phase-1.md`.

## Global Constraints

- **Zero data loss:** AI only adds (a tab, a note, blocks, new ERD tables/columns/relations) or changes the two Eisenhower axes after the user accepts a row; never deletes or overwrites. Every Apply is additive or reversible (Undo toast restores the previous axis values). A failed, cancelled or discarded run changes nothing. No schema change except optional new fields inside `aiSettings` (expand-only: `embeddingModel`).
- No commits until the user asks.
- Strict TS, no `any`. English identifiers, comments and UI copy.
- Prompts are internal: never shown, no free text beyond the user's own content; user content goes inside `dataBlock(...)`; `DATA_RULE` once in the system text.
- Data class: `people` for P2 and for Ask Workspace when people records are included; everything else `content`. Locked notes are never read unless unlocked in the session; a locked, unopened note is excluded.
- Entry points appear only when `features.ai` and a usable connection exist (and `features.aiPeople` for people tasks).
- Streaming never changes what is applied: the final parsed value is what Apply uses; a cut-off stream (`stopReason: 'length'`) blocks Apply like before.
- Images are sent only from a file the user picks or pastes into the dialog, shown as a thumbnail first; at most 4 images, 5 MB each.

## Review Focus

1. **Streaming failure modes:** server that ignores `stream:true` and returns JSON; stream that stops mid-event; abort mid-stream (desktop and web); renderer closed mid-stream (main cancels). Pinned in Task 1.
2. **Image safety:** oversize/wrong-type files rejected before sending; images never sent without being shown; text-only connection blocked with the reason. Pinned in Task 2.
3. **Apply never destroys:** ERD proposal never removes or renames existing tables/columns; Eisenhower Undo restores only if the axes are unchanged; new tab/note creation is atomic. Pinned in Tasks 5, 6, 8.
4. **People data:** 1:1 prep and workspace Q&A with people records route through the people gate; the chip names how many people and which time range. Pinned in Tasks 11 and 13.
5. **Hallucinated references:** Ask Workspace citations must point to retrieved sources; an answer citing a source that was not sent is flagged. Pinned in Task 13.
6. **Hostile model output:** HTML preview is sandboxed with no script; Mermaid goes through the Phase 1 checks; ERD output goes through a strict parser. Pinned in Tasks 8, 9, 12.
