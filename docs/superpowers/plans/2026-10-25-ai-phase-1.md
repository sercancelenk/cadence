# AI Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four Phase 1 AI features on the Phase 0a framework: Visualize (N1), Challenge my idea (N2), Break down (T1) and Feedback → SBI (P1).

**Architecture:** Each feature is one registry task (`src/lib/ai/prompts/*.ts`: versioned prompt, parser, fixtures) run by the existing `runAiTask`, shown in the existing `AiResultPanel`, and applied only on an explicit button. Notes and feedback are changed through the open editor's own transactions (so autosave, ⌘Z and the existing note version history apply); a new `AiEditorTarget` is the only way a dialog touches an editor. Task details are changed through the existing `updateTodoItem` path.

**Tech Stack:** React 18, TypeScript (strict, no `any`), TipTap/ProseMirror (`createRichTextExtensions`), Mermaid 11 (`mermaid.parse`), Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-24-ai-features-design.md` (sections 4, 5.1 to 5.8, 6 "Phase 1"). Foundation plan: `docs/superpowers/plans/2026-10-24-ai-foundation-phase-0a.md`.

## Global Constraints

- **Zero data loss** (AGENTS.md, `.cursor/rules/zero-data-loss.mdc`): AI only adds (a block, a checklist, new tasks) or replaces a selection the user explicitly accepted. No schema change in this plan. A failed, cancelled or discarded result changes nothing.
- No commits until the user asks (standing rule for this session). Tasks end with a green test run, not a commit.
- Strict TS, no `any`. English identifiers, comments and UI copy. Match the surrounding code's comment density.
- Prompts are internal: never shown, no free-text user input. User content goes inside `dataBlock(...)`; the system text carries `DATA_RULE` once. `promptVersion` starts at 1.
- Data class: Visualize, Challenge, Break down are `content`; SBI is `people` (`task.dataClass = 'people'`). Break down started from a person's task would pass `dataClass: 'people'` (not in this plan, see "Not in this plan").
- AI entry points appear only when `features.ai && hasUsableConnection(...)` (same gate as Extract tasks). People-class entry (SBI) also requires `features.aiPeople`.
- Each dialog renders through `AiResultPanel` with the context chips (`AiContextChip { label, detail, sent? }`), shows the `fellBack` note, and handles `blocked` / `error` the way `AITaskExtractorDialog.tsx` does.
- Reply capped by the engine; a reply with `stopReason === 'length'` is treated as truncated (see Review Focus 3).

## Review Focus

1. **Editor changed while a dialog was open.** Apply must never overwrite text it can no longer find: `replaceSelection` refuses, `insertBlocks` falls back to the end of the note and says so. Pinned in Task 2.
2. **Model output that is unsafe or unusable in a diagram.** Mermaid source with `click` callbacks, HTML, or a header that is not a supported diagram type is rejected by the parser; invalid syntax gets one repair run, then nothing is inserted. Pinned in Task 3.
3. **Truncated reply (`stopReason: 'length'`).** A cut-off diagram or step list is never applied: Apply is disabled and the panel says the reply was cut off. Pinned in Tasks 3 to 5.
4. **People data to a connection that is not allowed for it.** SBI is blocked with the Settings message and nothing is inserted or sent. Pinned in Task 6.
5. **Task details in every body format.** Appending a checklist keeps existing text for `prosemirror`, `markdown`, plain and empty bodies. Pinned in Task 5.
6. **Prompt injection in the user's text.** A text containing `</user_data>` or "ignore the rules" cannot leave its block; the parser still validates the reply. Pinned in the prompt tests of Tasks 3 to 6.

### Task 2: `AiEditorTarget`, the only bridge to an open editor

**Files:** Create `src/lib/ai/editorTarget.ts`, `src/lib/ai/editorTarget.test.ts`. Modify `src/lib/richTextSlashItems.ts` (+ test), `RichTextBubbleToolbar.tsx`, `RichTextEditor.tsx`, `RichTextDocumentPane.tsx`, `NotesBodyEditor.tsx`.

**Interfaces:**
- Produces:
  ```ts
  export type AiEditorTarget = {
    readonly selectedText: string;            // '' when the action started on the whole note
    isCurrent(): boolean;                     // document unchanged since the action started
    insertBlocks(nodes: JSONContent[], at: 'after-selection' | 'end'): 'after-selection' | 'end' | null;
    replaceSelection(text: string): boolean;  // inline text; \n becomes a hard break
  };
  export function createEditorTarget(editor: Editor, range: { from: number; to: number }, selectedText: string): AiEditorTarget;
  ```
  `insertBlocks`: returns `null` and changes nothing when the editor is destroyed or not editable. `at: 'after-selection'` inserts after the top-level block that holds `range.to` while `isCurrent()`; otherwise it appends at the end of the document and returns `'end'` (so the result is never lost). `replaceSelection`: returns `false` and changes nothing unless `isCurrent()`, `selectedText` is non-empty, and the text between `range` still equals `selectedText`.
- Changes: `onAiAction` becomes `(actionId: string, text: string, target: AiEditorTarget) => void` in `RichTextEditor`, `RichTextBubbleToolbar`, `RichTextDocumentPane`, `NotesBodyEditor` and in `createAiSlashItems`'s callback.

- [ ] **Step 1: Write failing tests** with a real editor (`new Editor({ extensions: createRichTextExtensions(), content })`, the pattern in `src/lib/richTextCodeBlock.test.ts`): (a) `insertBlocks([codeBlock mermaid], 'after-selection')` puts the block after the paragraph holding the selection and leaves all other text intact; (b) `'end'` appends after the last block; (c) after the document is edited, `isCurrent()` is `false`, `insertBlocks(..., 'after-selection')` returns `'end'` and the new block is the last node; (d) `replaceSelection('A\nB')` replaces exactly the range with `A`, hard break, `B` and `editor.commands.undo()` restores the original document; (e) after an edit elsewhere `replaceSelection` returns `false` and the document equals the edited one; (f) `replaceSelection` with `selectedText === ''` returns `false`; (g) a non-editable editor makes `insertBlocks` return `null`.
